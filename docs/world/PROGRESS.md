## 2026-10-08 M3a: actors driven from outside the loop (branch `feat/world-m3`)
Why: a real language-model call is async and slow; the engine loop is synchronous and transactional. Design: `run({ pauseOn })` stops BEFORE a wake-up of an external actor and leaves it scheduled; the driver `takeNext()`s it (clock moves to its time), does the work, and `applyStep(wake, result)` writes the result as history at the current virtual time. `advanceTo(ms)` spends virtual time outside the loop but refuses to jump over a scheduled wake-up (and still writes the daily snapshots); `contextFor(wake)` gives the driver exactly what the loop would give the actor, including its own random stream.
Test first (6 tests): the pause leaves history untouched; **an actor driven from outside writes byte-identical history to the same actor inside the loop** (for each of four actor sets, with a check that the work really happened outside: 12 to 1000+ external steps); stopping and reopening between external steps loses nothing; time cannot jump over a wake-up; `applyStep` validates; the external actor's random stream continues across steps and restarts.
Mutation check: 7 mutations, 6 caught from the start; "external step uses a fresh random stream" was NOT caught by the equivalence test (the loop uses the same `contextFor`, so both sides break together) and got its own test. Two mutations (a wake left in the schedule; a pause that never stops) made the test driver loop forever instead of failing: a reminder to put a step cap in drivers. Found by my own regression: after the refactor the step counter was incremented twice (the old M0 test (f) caught it).
Known flake: `handoff-timers` "a year of daily wake-ups" (Temporal time-skipping server) failed once while the machine's load average was 10 (three agent workers running tests); it passes alone and in a quiet full run.

## 2026-10-08 M3c: tape (recorded mode) and budgets (branch `feat/world-m3`)
`Tape`, `recording(brain, tape)`, `replaying(tape)`, `budgeted(primary, fallback, {unitsPerDay})` in `src/world/agents.ts`.
- **Recorded mode**: the tape holds, per agent and virtual time, the tool calls with their answers plus the brain's identity and cost. A replay re-issues the calls, compares each answer to the recorded one (a different world makes it throw "replay diverged"), and needs no brain: the fake model's call counter stays at 0 and the world hash equals the recorded run's. A shift that failed when recorded fails identically (the error carries the recorded brain/cost, otherwise the histories differ). Tape saved/loaded as JSON lines.
- **Budget**: units per agent per virtual day, rebuilt from `agent.shift` events at start (a restart mid-day does not refill it). When spent, the shift runs on the Tier 1 fallback, is marked `degraded` in the history and counted in the report. Zero budget never calls the model.
Evidence: 8 tests in `test/world-tape-budget.test.ts`; 13 mutations, 11 caught at first; the two gaps (replay past the end of the tape; a recorded failure) got tests and a bug fix (the replayed failure lost the brain's name/cost, found by the new test).
Not yet: a Tier 2 brain on a real model (M3d); several roles with handoffs/CaseContext as world events (M3e); the 30-day multi-agent acceptance.

## 2026-10-08 M3e: handoffs between agents as world events (branch `feat/world-m3`)
Design decision of mine: the synthetic tool set now HAS `ask_agent` (parameters `agent`, `request`, exactly the real tool's; id is case-insensitive, a leading @ is accepted). The earlier "deny by absence" test listed it as forbidden because in the live system it has side effects; in the world its effect is a history event, so the live tool stays unreachable and the synthetic one exists. `test/world-tools.test.ts` was changed accordingly (one name removed from the forbidden list).
How: `handoff.requested` (actor `tool:<caller>`) -> recipient's inbox (`Session.inbox()`, rebuilt from the history, so a restart finds it) -> `Session.reply()` becomes `handoff.completed` when the shift ends; a `watchdog` actor writes `handoff.escalated` once after 4 h if nobody answered. Replying to someone else's or an unknown request is an error. Brains: `rulesOps` asks `dev-1` about a ticket it cannot diagnose for 2 h (once while the question is open); `rulesDev` answers by diagnosing and fixing the service itself.
Evidence (`test/world-handoffs.test.ts`, 9 tests): with a log tool that lies 45 % and fails 25 % of the time, 4 seeds x 30 days, the team (operator + developer) has 22 % less customer pain than the operator alone (16417 vs 21053 severity-minutes, test asserts <90 %); one seed (f2) is worse for the team, so this is an average, not a guarantee. The number of resolved incidents did NOT differ (the operator gets a clean read eventually): my first assertion measured the wrong thing and failed; the right measure is time-to-resolution.
Mutation check: 13 mutations, 8 caught at first; the other 5: 2 equivalent (event cursor only affects speed; the watchdog already guards the escalated-over-completed overwrite), 3 real gaps got tests (inbox isolation, the 2 h patience and single question, the developer's real fix).
